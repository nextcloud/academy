## Why the ExApp frontend toolchain is different

In a PHP Nextcloud app, Webpack outputs to `js/` at the app root, and `\OCP\Util::addScript()` tells Nextcloud to include that file in the page. Nextcloud handles the rest.

ExApps work differently in two important ways:

**1. Assets are served by your FastAPI server, not Nextcloud.** Your compiled JavaScript, CSS, and images live in `ex_app/js/`, `ex_app/css/`, and `ex_app/img/`. When nc_py_api starts your server, it automatically mounts these folders to FastAPI's static file serving. Nextcloud (via AppAPI's proxy) fetches them from your server.

**2. The Webpack public path must point through the AppAPI proxy.** When the browser loads your JavaScript and that script tries to fetch chunks or assets, the URLs must go through `http://nextcloud.local/apps/app_api/proxy/pinboard_python/js/` — not directly to your FastAPI server's port. Without this, asset loading breaks in production (and in development, because the browser can't reach port 23000 directly).

Everything else — npm, Vue SFCs, `@nextcloud/vue`, `@nextcloud/axios` — is identical to the PHP track.

## Register the script in enabled_handler

Before setting up the build, update `enabled_handler` in `ex_app/lib/main.py` to register the compiled script with Nextcloud. This tells AppAPI which JavaScript file to load when a user opens the Pinboard top menu entry:

```python
# Run from: ~/pinboard-python/ (with .venv activated)
# Update enabled_handler in ex_app/lib/main.py

def enabled_handler(enabled: bool, nc: NextcloudApp) -> str:
    try:
        if enabled:
            nc.ui.resources.set_script(
                "top_menu",          # type — attaches to the top menu entry
                "pinboard",          # name of the top menu entry this script belongs to
                "js/pinboard-main",  # path relative to ex_app/, without .js extension
            )
            nc.ui.top_menu.register("pinboard", "Pinboard", "img/app.svg")
            nc.log(LogLvl.WARNING, "Pinboard enabled")
        else:
            nc.ui.resources.delete_script("top_menu", "pinboard", "js/pinboard-main")
            nc.ui.top_menu.unregister("pinboard")
            nc.log(LogLvl.WARNING, "Pinboard disabled")
    except Exception as e:
        return str(e)
    return ""
```

> **Order matters:** `set_script` must be called before `top_menu.register`. AppAPI associates the script with the menu entry, so the script registration must exist first.

## webpack.config.js

Create `webpack.config.js` in the project root. The critical ExApp-specific piece is the `output.path` — it must point to `ex_app/js/` so nc_py_api can serve the compiled files through FastAPI:

```js
/**
 * SPDX-FileCopyrightText: 2025 Your Name
 * SPDX-License-Identifier: AGPL-3.0-or-later
 */

const path = require('path')
const webpackConfig = require('@nextcloud/webpack-vue-config')

module.exports = {
  ...webpackConfig,
  entry: {
    main: path.join(__dirname, 'src', 'main.js'),
  },
  output: {
    ...webpackConfig.output,
    path: path.join(__dirname, 'ex_app', 'js'),
    publicPath: '',  // overridden at runtime by bootstrap.js
  },
}
```

> **`output.path: ex_app/js/`** — this is the only structural difference from the PHP track's `webpack.js`. The PHP track outputs to `js/` at the project root; ExApps output to `ex_app/js/` so nc_py_api picks it up.

> **`publicPath: ''`** — set empty here. The real public path is set at runtime in `bootstrap.js` via `__webpack_public_path__`. This is necessary because the proxy URL contains the Nextcloud base URL which varies per installation.

## src/constants/AppAPI.js

Create `src/constants/AppAPI.js`. These constants are used throughout the frontend to build correct URLs through the AppAPI proxy:

```js
/**
 * SPDX-FileCopyrightText: 2025 Your Name
 * SPDX-License-Identifier: AGPL-3.0-or-later
 */

export const EX_APP_ID = 'pinboard_python'
export const EX_APP_MENU_ENTRY_NAME = 'pinboard'
export const APP_API_PROXY_URL_PREFIX = '/apps/app_api/proxy'
export const APP_API_ROUTER_BASE = '/apps/app_api/embedded'
```

**`EX_APP_ID`** — must exactly match the app ID in `info.xml` and your Makefile. Used to build all proxy URLs.

**`APP_API_PROXY_URL_PREFIX`** — the AppAPI proxy path. All API calls from Vue go through here: `${APP_API_PROXY_URL_PREFIX}/${EX_APP_ID}/pins` becomes `/apps/app_api/proxy/pinboard_python/pins`.

**`APP_API_ROUTER_BASE`** — the base path for Vue Router when running inside the AppAPI embedded frame. Used in B-06 for routing.

## src/bootstrap.js

Create `src/bootstrap.js`. This runs before your Vue app mounts and sets the critical `__webpack_public_path__` so the browser fetches assets via the AppAPI proxy:

```js
/**
 * SPDX-FileCopyrightText: 2025 Your Name
 * SPDX-License-Identifier: AGPL-3.0-or-later
 */

import Vue from 'vue'
import { translate, translatePlural } from '@nextcloud/l10n'
import { generateUrl } from '@nextcloud/router'
import { APP_API_PROXY_URL_PREFIX, EX_APP_ID } from './constants/AppAPI.js'
import { getCSPNonce } from '@nextcloud/auth'

Vue.prototype.t = translate
Vue.prototype.n = translatePlural
Vue.prototype.OC = window.OC
Vue.prototype.OCA = window.OCA

// Tell Webpack where to load chunks and assets — must go through the AppAPI proxy
// eslint-disable-next-line
__webpack_public_path__ = generateUrl(`${APP_API_PROXY_URL_PREFIX}/${EX_APP_ID}/js/`)

// Set the CSP nonce for inline scripts
// eslint-disable-next-line
__webpack_nonce__ = getCSPNonce()
```

**`__webpack_public_path__`** — a magic Webpack global that sets the base URL for loading JS chunks and assets at runtime. By setting it to the AppAPI proxy URL, any dynamic import or asset reference will correctly route through Nextcloud rather than trying to reach your FastAPI port directly. This is the most important ExApp-specific frontend difference from PHP apps.

**`generateUrl()`** from `@nextcloud/router` — builds a correct absolute URL that accounts for the Nextcloud installation's base path (some instances are installed at a sub-path like `/nextcloud/`).

## src/main.js

Create `src/main.js` — the Vue entry point:

```js
/**
 * SPDX-FileCopyrightText: 2025 Your Name
 * SPDX-License-Identifier: AGPL-3.0-or-later
 */

import './bootstrap.js'
import Vue from 'vue'
import App from './App.vue'

const app = new Vue({
  render: h => h(App),
})

app.$mount('#app-pinboard_python')
```

> **`#app-pinboard_python`** — the mount point ID for ExApps follows the pattern `app-<appid>`. AppAPI injects a div with this ID into the top menu page automatically. It must match your app ID exactly.

> **`import './bootstrap.js'` first** — `bootstrap.js` must run before Vue is initialised because it sets `__webpack_public_path__`. Importing it at the top of `main.js` guarantees correct execution order.

## Common problems

**`pinboard-main.js` loads from `localhost:23000` instead of the proxy**  
`__webpack_public_path__` isn't being set. Check that `main.js` imports `bootstrap.js` as its first line, and that `bootstrap.js` contains the `__webpack_public_path__` assignment.

**Blank page with no console errors**  
The mount point ID doesn't match. Check that `app.$mount('#app-pinboard_python')` in `main.js` uses the exact same app ID as your registration — `pinboard_python` with an underscore, not a hyphen.

**`set_script` registration fails**  
Check the script path argument — `"js/pinboard-main"` is relative to `ex_app/` and must not include the `.js` extension. AppAPI appends it automatically.

**`ex_app/js/` is empty after `npm run dev`**  
Check `webpack.config.js` — `output.path` must be an absolute path. Use `path.join(__dirname, 'ex_app', 'js')` not a relative path string.

**`Module not found: @nextcloud/auth`**  
Run `npm install` from the project root. The `node_modules` directory must be in `~/pinboard-python/`, not in `src/`.
