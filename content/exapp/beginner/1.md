# Module B-01: Environment Setup

**Track:** ExApp Track — Beginner  
**Estimated time:** 60 minutes  
**You'll have when done:** A running Nextcloud 34 development instance with AppAPI enabled, a registered `manual_install` daemon, a working Python environment with `nc_py_api`, and a verified development loop — your ExApp skeleton connects to Nextcloud and logs a message.

---

## Why ExApps need a different setup

A PHP app runs *inside* Nextcloud's PHP process — Nextcloud loads it directly. An ExApp runs *outside* Nextcloud as a separate process — a standalone Python server that Nextcloud communicates with over HTTP.

This means the development environment has two moving parts instead of one:

1. **Nextcloud** — the docker-dev instance, same as always
2. **Your ExApp** — a FastAPI server running on your machine, outside the container

The bridge between them is **AppAPI** — a Nextcloud app that acts as the broker. AppAPI knows how to discover, launch, and communicate with external apps. During development you use a special `manual_install` daemon that tells AppAPI "I'll handle running the app myself" — no Docker builds required on every change.

This architecture is what makes ExApps powerful: your Python process can use any library, any runtime, any AI framework. It's also what makes the setup slightly more involved than PHP.

## Part 1: Get Nextcloud running

### Clone and bootstrap nextcloud-docker-dev

The `nextcloud-docker-dev` repository sets up a full Nextcloud development instance in Docker. The bootstrap script clones the Nextcloud server source and configures everything.

```bash
# Run from: ~/
git clone https://github.com/nextcloud/nextcloud-docker-dev
cd nextcloud-docker-dev
sudo ./bootstrap.sh
docker compose up -d
```

`bootstrap.sh` adds a hosts entry for `nextcloud.local`. Verify it:

```bash
# Run from: ~/nextcloud-docker-dev/
# Check Nextcloud is running
./scripts/occ.sh nextcloud -- status
# Expected: installed: true, version: 34.x.x
```

> **This can take 10–20 minutes on first run.** The bootstrap script clones the full Nextcloud server repository and pulls Docker images. If it looks frozen, it probably isn't — be patient.

### Enable debug mode and verbose logging

```bash
# Run from: ~/nextcloud-docker-dev/
cat > data/shared/config.php << 'EOF'
<?php
$CONFIG = [
    'debug' => true,
    'loglevel' => 0,
];
EOF

docker compose restart nextcloud
```

### Tail the logs

In a separate terminal, leave this running while you develop:

```bash
# Run from: ~/nextcloud-docker-dev/
docker compose exec nextcloud bash -c \
  "tail -f /var/www/html/data/nextcloud.log | jq ."
```

> `jq` is pre-installed in the PHP images. Tail from inside the container — tailing the file from the host misses events across Docker's filesystem layer.

### Test users

## Part 2: Install and configure AppAPI

### What AppAPI is

AppAPI is the Nextcloud app that makes ExApps possible. It acts as the broker between Nextcloud and your external Python server — handling authentication, lifecycle management (enable/disable), and routing requests. Every ExApp is registered through AppAPI.

> **AppAPI ships with Nextcloud 30+ and is automatically installed.** On NC34 it should already be present. Confirm it's enabled:

```bash
# Run from: ~/nextcloud-docker-dev/
./scripts/occ.sh nextcloud -- app:list --enabled | grep app_api
# Expected: app_api: x.x.x
```

If it's not enabled:

```bash
# Run from: ~/nextcloud-docker-dev/
./scripts/occ.sh nextcloud -- app:enable app_api
```

### Register the manual_install daemon

A **deploy daemon** tells AppAPI how to launch and reach ExApps. For production this is Docker — AppAPI builds and runs containers automatically. For development, the `manual_install` daemon tells AppAPI: "the developer will run the app manually; just connect to it on the port I specify."

Register it once — it persists until you reset the environment.

**Option A — via the UI:** Go to **Administration settings → AppAPI → Deploy Daemons** and click **+ Register Daemon**. Select "Manual install" as the configuration template. Leave all fields as default except Nextcloud URL — set that to `0`. Click Register.

**Option B — via the terminal:**

```bash
# Run from: ~/nextcloud-docker-dev/
./scripts/occ.sh nextcloud -- app_api:daemon:register \
  manual_install \
  "Manual Install" \
  manual-install \
  http \
  host.docker.internal \
  0
```

The arguments are: `name`, `display-name`, `accepts-deploy-id`, `protocol`, `host`, `nextcloud_url`.

The `0` for `nextcloud_url` is correct for `manual_install` — it tells AppAPI to pass the Nextcloud URL to your ExApp via the `NEXTCLOUD_URL` environment variable at registration time rather than hardcoding it in the daemon.

`host.docker.internal` is the key piece: it resolves to your host machine from inside the Docker container. When AppAPI (running inside the Nextcloud container) needs to call your ExApp, it sends requests to `http://host.docker.internal:PORT` — which reaches your FastAPI server running on your laptop outside Docker. This is the entire basis of the `manual_install` development loop.

> **On Linux**, `host.docker.internal` is not automatically available. Add this to your `docker-compose.override.yml` and restart:
> ```yaml
> services:
>   nextcloud:
>     extra_hosts:
>       - "host.docker.internal:host-gateway"
> ```

Verify the daemon registered:

```bash
# Run from: ~/nextcloud-docker-dev/
./scripts/occ.sh nextcloud -- app_api:daemon:list
# Expected: manual_install listed with type manual-install
```

## Part 3: Set up your Python environment

### Python version

ExApps with `nc_py_api` require **Python 3.10 or later**. Check your version:

```bash
# Run from: anywhere
python3 --version
# Expected: Python 3.10.x or higher
```

If you're on an older version, install Python 3.10+ via your package manager (`apt install python3.10` on Ubuntu, `brew install python@3.12` on macOS).

### Create a virtual environment

Always use a virtual environment for ExApp development — it keeps `nc_py_api` and other dependencies isolated from your system Python:

```bash
# Run from: ~/  (or wherever you keep projects)
# Create a directory for the Pinboard ExApp
mkdir pinboard-python && cd pinboard-python

# Create and activate the virtual environment
python3 -m venv .venv
source .venv/bin/activate      # macOS/Linux
# .venv\Scripts\activate       # Windows

# Verify you're in the venv
which python3
# Expected: .../pinboard-python/.venv/bin/python3
```

> **Always activate the venv** before working on the project. Your shell prompt will show `(.venv)` when it's active. If you open a new terminal, run `source .venv/bin/activate` again.

### Install nc_py_api

```bash
# Run from: ~/pinboard-python/ (with .venv activated)
pip install "nc_py_api[app]==0.30.2"
```

The `[app]` extra installs FastAPI, uvicorn, and everything else needed to run an ExApp server, in addition to the base nc_py_api client library.

Verify the installation:

```bash
# Run from: ~/pinboard-python/ (with .venv activated)
python3 -c "import nc_py_api; print(nc_py_api.__version__)"
# Expected: 0.30.2
```

## Part 4: The skeleton app and development loop

### Create the skeleton

Create `main.py` in your `pinboard-python` directory:

```python
# SPDX-FileCopyrightText: 2025 Your Name
# SPDX-License-Identifier: AGPL-3.0-or-later

from contextlib import asynccontextmanager

from fastapi import FastAPI
from nc_py_api import NextcloudApp
from nc_py_api.ex_app import AppAPIAuthMiddleware, LogLvl, run_app, set_handlers


@asynccontextmanager
async def lifespan(app: FastAPI):
    set_handlers(app, enabled_handler)
    yield


APP = FastAPI(lifespan=lifespan)
APP.add_middleware(AppAPIAuthMiddleware)


def enabled_handler(enabled: bool, nc: NextcloudApp) -> str:
    if enabled:
        nc.log(LogLvl.WARNING, f"Pinboard ExApp enabled on {nc.app_cfg.app_name}")
    else:
        nc.log(LogLvl.WARNING, f"Pinboard ExApp disabled")
    return ""


if __name__ == "__main__":
    run_app("main:APP", log_level="trace")
```

### Understand the skeleton

**`set_handlers(app, enabled_handler)`** — registers the `/enabled` endpoint that AppAPI calls when an admin enables or disables your app. This is where you register your app's features (menus, UI elements, background jobs) when enabled, and unregister them when disabled.

**`AppAPIAuthMiddleware`** — authenticates every incoming request from AppAPI using a shared secret. Without this, any caller could hit your endpoints. This should always be added globally.

**`enabled_handler`** — called by AppAPI during enable/disable. Must return an empty string on success or a short error description on failure. The `nc` parameter is an authenticated `NextcloudApp` instance you can use immediately to make API calls — except user-context calls, since no user is active at enable time.

**`run_app`** — a thin wrapper around `uvicorn.run` that reads `APP_HOST` and `APP_PORT` from environment variables. You'll set these when running the app.

### The development loop

For each development session:

**1. Set environment variables and start your app:**

```bash
# Run from: ~/pinboard-python/ (with .venv activated)
APP_ID=pinboard_python APP_PORT=23000 APP_HOST=0.0.0.0 APP_SECRET=your_dev_secret_here APP_VERSION=0.1.0 AA_VERSION=2.0.0 NEXTCLOUD_URL=http://nextcloud.local python3 ex_app/lib/main.py
# Expected: Uvicorn running on http://0.0.0.0:23000
```

**2. Register the app with AppAPI** (in a second terminal):

```bash
# Run from: ~/nextcloud-docker-dev/
./scripts/occ.sh nextcloud -- app_api:app:unregister pinboard_python --silent --force || true
./scripts/occ.sh nextcloud -- app_api:app:register pinboard_python manual_install \
  --json-info '{"id":"pinboard_python","name":"Pinboard","daemon_config_name":"manual_install","version":"0.1.0","secret":"your_dev_secret_here","port":23000}' \
  --force-scopes \
  --wait-finish
```

**3. Check the logs:**

In your log tail terminal you should see a line from `enabled_handler`:

```
"message": "Pinboard ExApp enabled on pinboard_python"
```

And in your uvicorn terminal you'll see the request from AppAPI hitting `/enabled`.

> **The `--wait-finish` flag** blocks until AppAPI has finished the enable process. Without it the command returns immediately and the app may not be fully registered yet.

### Re-registering during development

When you change `main.py` and restart the server, you need to re-register:

```bash
# Run from: ~/nextcloud-docker-dev/
./scripts/occ.sh nextcloud -- app_api:app:unregister pinboard_python --silent --force || true
./scripts/occ.sh nextcloud -- app_api:app:register pinboard_python manual_install \
  --json-info '{"id":"pinboard_python","name":"Pinboard","daemon_config_name":"manual_install","version":"0.1.0","secret":"your_dev_secret_here","port":23000}' \
  --force-scopes \
  --wait-finish
```

> **Tip:** Add these to a `Makefile` so you're not retyping them. Module B-03 covers the standard ExApp Makefile conventions.

## Common problems

**`host.docker.internal` doesn't resolve (Linux)**  
See the note in the daemon registration section above — add `extra_hosts` to `docker-compose.override.yml` and restart with `docker compose down && docker compose up -d`.

**`app_api` not found / `app_api:daemon:register` command not found**  
AppAPI isn't enabled. Run `./scripts/occ.sh nextcloud -- app:enable app_api` and try again.

**AppAPI can't reach your app (timeout during register)**  
Check that your FastAPI server is actually running (`python3 ex_app/lib/main.py` is active and shows "Uvicorn running"). Check the port matches — `APP_PORT` in your environment and the `"port"` in the JSON info must be identical. Check your firewall isn't blocking the port.

**`APP_SECRET` mismatch error**  
The `APP_SECRET` in your environment variables and the `"secret"` in the `app_api:app:register` JSON must match exactly. They're used to authenticate requests between AppAPI and your server.

**`ModuleNotFoundError: No module named 'nc_py_api'`**  
Your virtual environment isn't activated. Run `source .venv/bin/activate` and try again.

**Version mismatch warning from AppAPI**  
If AppAPI warns about a version mismatch between `nc_py_api` and the installed AppAPI app, check `./scripts/occ.sh nextcloud -- app:list --enabled | grep app_api` and compare with `nc_py_api.__version__`. For NC34, `nc_py_api` 0.30.x should be compatible.
