## Why ExApps own their database

In a PHP Nextcloud app, the database is shared with Nextcloud — your tables live alongside Nextcloud's own tables in MySQL, MariaDB, or PostgreSQL, and Nextcloud's migration system manages schema changes.

ExApps work differently. **Your process owns your database entirely.** There is no shared database, no `occ migrations:generate`, no `QBMapper`. You choose the database technology, you manage the schema, and you're responsible for keeping data consistent across updates.

This is actually simpler in many ways — there's no abstraction layer to understand, no surprise about what SQL gets generated, and no dependency on Nextcloud's database backend. Your ExApp is a standard Python application that happens to talk to Nextcloud.

**Where the data lives:** AppAPI creates a Docker volume named `nc_app_<app_id>_data` for each ExApp and mounts it into the container. The path inside the container is passed via the `APP_PERSISTENT_STORAGE` environment variable. This volume persists across container restarts and updates — it's the right place to store your SQLite file.

In the `manual_install` development setup there's no Docker container, so `APP_PERSISTENT_STORAGE` isn't set automatically. You'll add it to the `make run` command and point it to a local directory.

---

## Database technology choices

For the course we use **SQLite** — it's built into Python, requires no server, and is perfectly capable for a personal pinboard app. For production deployments with higher concurrency or multiple ExApp instances, you'd swap to PostgreSQL or MySQL.

SQLAlchemy makes this swap trivial — the only change is the connection URL:

| Backend | Connection URL |
|---------|----------------|
| SQLite (development) | `sqlite:////path/to/pinboard.db` |
| SQLite (production via volume) | `sqlite:////nc_app_pinboard_python_data/pinboard.db` |
| PostgreSQL | `postgresql+psycopg2://user:pass@host/dbname` |
| MySQL | `mysql+pymysql://user:pass@host/dbname` |

Your Python code — models, queries, session management — stays identical across all backends. Only the URL changes, and that comes from an environment variable, so it's a configuration change rather than a code change.

## The Pin model

Create `ex_app/lib/models.py`:

```python
# SPDX-FileCopyrightText: 2025 Your Name
# SPDX-License-Identifier: AGPL-3.0-or-later

import time
from sqlalchemy import Boolean, Column, Integer, String, create_engine
from sqlalchemy.orm import DeclarativeBase, Session


class Base(DeclarativeBase):
    pass


class Pin(Base):
    __tablename__ = "pins"

    id         = Column(Integer, primary_key=True, autoincrement=True)
    user_id    = Column(String(64), nullable=False, index=True)
    url        = Column(String(4000), nullable=False)
    title      = Column(String(255), nullable=True)
    favourited = Column(Boolean, nullable=False, default=False)
    created_at = Column(Integer, nullable=False, default=lambda: int(time.time()))

    def to_dict(self) -> dict:
        return {
            "id":         self.id,
            "user_id":    self.user_id,
            "url":        self.url,
            "title":      self.title,
            "favourited": self.favourited,
            "created_at": self.created_at,
        }
```

### What each part does

**`DeclarativeBase`** — SQLAlchemy 2.x's base class for models. All models that inherit from `Base` will have their tables created by `Base.metadata.create_all()`.

**`__tablename__ = "pins"`** — the actual SQL table name. Simple and descriptive — no namespace prefix needed since your ExApp owns the entire database.

**`user_id = Column(String(64), ..., index=True)`** — 64 characters matches Nextcloud's maximum user ID length. The `index=True` creates a database index, making `WHERE user_id = ?` queries fast even with many rows.

**`created_at = Column(Integer, ..., default=lambda: int(time.time()))`** — stored as a Unix epoch integer, consistent with the PHP track's approach. The `lambda` means the default is evaluated at insert time, not at class definition time.

**`to_dict()`** — converts the model to a plain dict for JSON serialisation. FastAPI can't serialise SQLAlchemy model objects directly, so you call `to_dict()` before returning from an endpoint.

## Database initialisation and session management

Create `ex_app/lib/database.py`:

```python
# SPDX-FileCopyrightText: 2025 Your Name
# SPDX-License-Identifier: AGPL-3.0-or-later

import os
from pathlib import Path

from sqlalchemy import create_engine
from sqlalchemy.orm import Session, sessionmaker

from models import Base


def get_db_path() -> str:
    """Return the path to the SQLite database file.

    In production (Docker), APP_PERSISTENT_STORAGE is set by AppAPI.
    In development (manual_install), falls back to a local directory.
    """
    storage = os.environ.get("APP_PERSISTENT_STORAGE", "data")
    Path(storage).mkdir(parents=True, exist_ok=True)
    return str(Path(storage) / "pinboard.db")


def create_db_engine():
    db_path = get_db_path()
    engine = create_engine(
        f"sqlite:///{db_path}",
        connect_args={"check_same_thread": False},  # needed for FastAPI's threaded model
    )
    return engine


# Module-level engine and session factory — created once on startup
engine = create_db_engine()
SessionLocal = sessionmaker(bind=engine, autocommit=False, autoflush=False)


def init_db():
    """Create all tables if they don't exist. Safe to call multiple times."""
    Base.metadata.create_all(engine)


def get_session():
    """FastAPI dependency — yields a database session and closes it after the request."""
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()
```

### What each part does

**`get_db_path()`** — reads `APP_PERSISTENT_STORAGE` from the environment. In production, AppAPI sets this to the mounted volume path (`/nc_app_pinboard_python_data/`). In development, it falls back to a `data/` subdirectory in your project. The `Path(storage).mkdir(parents=True, exist_ok=True)` ensures the directory exists.

**`check_same_thread=False`** — SQLite's default safety check prevents the same connection from being used across threads. FastAPI uses threads for concurrent requests, so you must disable this check. SQLAlchemy's connection pool handles thread safety correctly with this setting.

**`init_db()`** — calls `create_all()` which creates any tables that don't exist yet. If the table already exists, it's left unchanged. This is your schema migration for now — in B-04 Intermediate you'd add Alembic for proper migrations.

**`get_session()`** — a FastAPI generator dependency. The `try/finally` ensures the session is always closed even if the handler raises an exception, preventing connection leaks.

## Update main.py

Wire everything together in `ex_app/lib/main.py`:

```python
# SPDX-FileCopyrightText: 2025 Your Name
# SPDX-License-Identifier: AGPL-3.0-or-later

from contextlib import asynccontextmanager
from typing import Annotated

from fastapi import Depends, FastAPI, HTTPException
from fastapi.responses import JSONResponse
from pydantic import BaseModel
from sqlalchemy.orm import Session

from nc_py_api import NextcloudApp
from nc_py_api.ex_app import AppAPIAuthMiddleware, LogLvl, nc_app, run_app, set_handlers

from database import get_session, init_db
from models import Pin


class PinRequest(BaseModel):
    url: str
    title: str | None = None
    favourited: bool = False


@asynccontextmanager
async def lifespan(app: FastAPI):
    init_db()  # create tables on startup
    set_handlers(app, enabled_handler)
    yield


APP = FastAPI(lifespan=lifespan)
APP.add_middleware(AppAPIAuthMiddleware)


def enabled_handler(enabled: bool, nc: NextcloudApp) -> str:
    try:
        if enabled:
            nc.ui.top_menu.register("pinboard", "Pinboard", "img/app.svg")
            nc.log(LogLvl.WARNING, "Pinboard enabled")
        else:
            nc.ui.top_menu.unregister("pinboard")
            nc.log(LogLvl.WARNING, "Pinboard disabled")
    except Exception as e:
        return str(e)
    return ""


@APP.get("/pins")
async def get_pins(
    nc: Annotated[NextcloudApp, Depends(nc_app)],
    db: Session = Depends(get_session),
):
    """Return all pins for the current user, newest first."""
    pins = (
        db.query(Pin)
        .filter(Pin.user_id == nc.user)
        .order_by(Pin.created_at.desc())
        .all()
    )
    nc.log(LogLvl.DEBUG, f"get_pins: {len(pins)} pins for user {nc.user}")
    return [p.to_dict() for p in pins]


@APP.post("/pins")
async def create_pin(
    pin: PinRequest,
    nc: Annotated[NextcloudApp, Depends(nc_app)],
    db: Session = Depends(get_session),
):
    """Create a new pin for the current user."""
    new_pin = Pin(
        user_id=nc.user,
        url=pin.url,
        title=pin.title,
        favourited=pin.favourited,
    )
    db.add(new_pin)
    db.commit()
    db.refresh(new_pin)
    nc.log(LogLvl.DEBUG, f"create_pin: created pin {new_pin.id} for user {nc.user}")
    return JSONResponse(content=new_pin.to_dict(), status_code=201)
```

### Safety rules — same principles as the PHP track

**Always filter by `user_id`** — every query uses `filter(Pin.user_id == nc.user)`. Never query without this filter. A pin that exists but belongs to another user should be completely invisible.

**`db.refresh(new_pin)`** — after `db.commit()`, SQLAlchemy needs to reload the object from the database to populate server-generated values (the auto-incremented `id`, the `created_at` default). Without this, `new_pin.id` would be `None`.

## Common problems

**`ModuleNotFoundError: No module named 'models'`**  
SQLAlchemy is importing `models` but Python's path doesn't include `ex_app/lib/`. The `run_app()` call in `main.py` sets the working directory. If running manually instead of via `make run`, make sure you're running from `ex_app/lib/`: `cd ex_app/lib && python3 main.py`.

**`OperationalError: unable to open database file`**  
The `data/` directory doesn't exist. Either run `mkdir -p data` or let `get_db_path()` create it — check that `APP_PERSISTENT_STORAGE=./data` is set in your `make run` command.

**`id` is `None` after insert**  
You're missing `db.refresh(new_pin)` after `db.commit()`. SQLAlchemy doesn't reload server-generated values automatically.

**Pins from a previous session appear for all users**  
You're missing the `filter(Pin.user_id == nc.user)` in a query. Every query that returns pins must include this filter.

**`check_same_thread` error from SQLite**  
You're missing `connect_args={"check_same_thread": False}` in `create_engine()`. FastAPI handles concurrent requests across threads — SQLite's default single-thread check must be disabled.
