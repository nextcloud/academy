## The request flow in detail

Before writing any endpoints, it's worth understanding the full path a request takes from a user's browser to your Python code and back:

```
# Conceptual flow — not a command
User clicks Pinboard in the nav bar
        │
        ▼
Nextcloud (nextcloud.local)
        │  AppAPI proxy forwards to ExApp
        ▼
http://host.docker.internal:23000/  ← your FastAPI server
        │
        your endpoint handler runs
        │  nc_py_api calls back to Nextcloud if needed
        ▼
Nextcloud OCS API (files, users, notifications...)
        │
        ▼
Response back through AppAPI → Nextcloud → browser
```

Two important things flow in both directions:

**Nextcloud → ExApp:** Every request from AppAPI to your server carries the `AUTHORIZATION-APP-API` header with the shared secret and the current user's ID. `AppAPIAuthMiddleware` validates this and makes the user context available.

**ExApp → Nextcloud:** When your handler calls `nc.files`, `nc.notifications`, or any other nc_py_api API, it makes authenticated OCS requests back to Nextcloud. The `nc` object already has everything it needs — you just call methods on it.

## Getting the NextcloudApp instance in endpoints

In `enabled_handler` the `nc: NextcloudApp` parameter was provided by `set_handlers()`. In regular FastAPI endpoints you get it differently — via a FastAPI dependency:

```python
# Run from: ~/pinboard-python/ (with .venv activated)
# This is a code pattern — add to ex_app/lib/main.py

from typing import Annotated
from fastapi import Depends
from nc_py_api import NextcloudApp
from nc_py_api.ex_app import nc_app

@APP.get("/pins")
async def get_pins(nc: Annotated[NextcloudApp, Depends(nc_app)]):
    # nc.user is the currently authenticated Nextcloud user
    # nc.files, nc.notifications, etc. are all available
    return []
```

`Depends(nc_app)` is FastAPI's dependency injection — before your handler runs, FastAPI calls `nc_app()` which validates the AppAPI authentication headers and returns an authenticated `NextcloudApp` instance scoped to the current request and user.

**`nc.user`** — the user ID of the person whose action triggered this request. Always a non-empty string in authenticated endpoints. This is what you'll use to scope database queries in B-05, exactly as `$userId` was used in the PHP track.

**`nc.app_cfg`** — metadata about your running ExApp: `nc.app_cfg.app_name`, `nc.app_cfg.app_version`, `nc.app_cfg.app_secret`.

## Logging

Write to Nextcloud's log file with `nc.log()`:

```python
from nc_py_api.ex_app import LogLvl

nc.log(LogLvl.DEBUG,   "Detailed trace message")
nc.log(LogLvl.INFO,    "Normal event")
nc.log(LogLvl.WARNING, "Something unexpected but recoverable")
nc.log(LogLvl.ERROR,   "An operation failed")
```

The log appears in the same stream you're tailing from B-01:

```bash
# Run from: ~/nextcloud-docker-dev/
docker compose exec nextcloud bash -c \
  "tail -f /var/www/html/data/nextcloud.log | jq ."
```

Each entry will show your ExApp ID as the source:

```json
{
  "reqId": "...",
  "level": 2,
  "time": "2025-06-01T12:00:00+00:00",
  "remoteAddr": "",
  "user": "--",
  "app": "app_api",
  "method": "",
  "url": "--",
  "message": "Your message here",
  "userAgent": "--",
  "version": "34.0.0.0"
}
```

> **Don't use `print()` for production logging.** `print()` goes to uvicorn's stdout — only visible in your terminal, not in the Nextcloud log that admins check. Use `nc.log()` for anything that matters. `print()` is fine for quick debugging during development.

## Registering the navigation entry

Pinboard needs to appear in Nextcloud's top navigation bar. Unlike PHP apps where this is declared in `info.xml`, ExApps register navigation entries programmatically in `enabled_handler`.

The registration call is `nc.ui.top_menu.register()` and it must be balanced with `nc.ui.top_menu.unregister()` when the app is disabled. AppAPI is idempotent — calling register when already registered won't fail.

You also need an icon. Create a placeholder SVG at `ex_app/img/app.svg`:

```bash
# Run from: ~/pinboard-python/
mkdir -p ex_app/img
cat > ex_app/img/app.svg << 'EOF'
<!--
  SPDX-FileCopyrightText: 2025 Your Name
  SPDX-License-Identifier: AGPL-3.0-or-later
-->
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 24 24" fill="#fff">
  <path d="M17 3H7a2 2 0 0 0-2 2v16l7-3 7 3V5a2 2 0 0 0-2-2z"/>
</svg>
EOF
```

> **`fill="#fff"`** — Nextcloud loads this as an `<img>` element and applies a CSS filter to theme it. The fill must be white for the filter to work correctly. This is the same rule as in the PHP track.

Now update `enabled_handler` in `ex_app/lib/main.py` to register the navigation entry:

```python
# Run from: ~/pinboard-python/ (with .venv activated)
# Update enabled_handler in ex_app/lib/main.py

def enabled_handler(enabled: bool, nc: NextcloudApp) -> str:
    try:
        if enabled:
            nc.ui.top_menu.register(
                "pinboard",           # unique name — used to identify this entry
                "Pinboard",           # display name shown in the nav bar
                "img/app.svg",        # icon path, relative to ex_app/ root
            )
            nc.log(LogLvl.WARNING, f"Pinboard enabled — navigation entry registered")
        else:
            nc.ui.top_menu.unregister("pinboard")
            nc.log(LogLvl.WARNING, f"Pinboard disabled — navigation entry removed")
    except Exception as e:
        return str(e)
    return ""
```

> **Always wrap `enabled_handler` in try/except.** If an exception propagates uncaught, AppAPI receives a 500 response and the enable fails with a confusing error. Return the exception string instead — AppAPI shows it to the administrator as a readable error message.

## The first endpoints

Add three things to `ex_app/lib/main.py`:

1. The imports needed for endpoints
2. A `GET /pins` endpoint returning an empty list
3. A stubbed `POST /pins` endpoint

```python
# Run from: ~/pinboard-python/ (with .venv activated)
# Add to ex_app/lib/main.py

from typing import Annotated
from fastapi import Depends
from fastapi.responses import JSONResponse
from pydantic import BaseModel
from nc_py_api import NextcloudApp
from nc_py_api.ex_app import nc_app


class PinRequest(BaseModel):
    url: str
    title: str | None = None


@APP.get("/pins")
async def get_pins(nc: Annotated[NextcloudApp, Depends(nc_app)]):
    """Return all pins for the current user."""
    nc.log(LogLvl.DEBUG, f"get_pins called by user: {nc.user}")
    # No database yet — returns empty list until B-05
    return []


@APP.post("/pins")
async def create_pin(
    pin: PinRequest,
    nc: Annotated[NextcloudApp, Depends(nc_app)],
):
    """Create a new pin for the current user."""
    nc.log(LogLvl.DEBUG, f"create_pin called by user: {nc.user}, url: {pin.url}")
    # No persistence yet — stub response until B-05
    return JSONResponse(
        content={"id": 1, "url": pin.url, "title": pin.title, "user_id": nc.user},
        status_code=201,
    )
```

### What's happening here

**`PinRequest`** is a Pydantic model. FastAPI uses it to automatically parse and validate the JSON request body. If the request arrives without a `url` field, FastAPI returns a 422 before your handler even runs. This is the Python equivalent of PHP's `$request->getParam()` — but with automatic validation.

**`Annotated[NextcloudApp, Depends(nc_app)]`** — the same pattern as above. Every endpoint that needs to know who the user is, or needs to call back to Nextcloud, uses this. Endpoints that don't need Nextcloud context (health checks, public endpoints) can omit it.

**`nc.user`** — always non-empty in endpoints protected by `AppAPIAuthMiddleware`. This is the Nextcloud user ID — the same string that gets stored in `user_id` columns in the database in B-05.

**`status_code=201`** for POST — correct HTTP semantics: 200 means "OK, here's data", 201 means "I created something". FastAPI defaults to 200; for create operations return 201 explicitly.

## The full main.py

Here is the complete `ex_app/lib/main.py` at this stage:

```python
# SPDX-FileCopyrightText: 2025 Your Name
# SPDX-License-Identifier: AGPL-3.0-or-later

from contextlib import asynccontextmanager
from typing import Annotated

from fastapi import Depends, FastAPI
from fastapi.responses import JSONResponse
from pydantic import BaseModel

from nc_py_api import NextcloudApp
from nc_py_api.ex_app import AppAPIAuthMiddleware, LogLvl, nc_app, run_app, set_handlers


class PinRequest(BaseModel):
    url: str
    title: str | None = None


@asynccontextmanager
async def lifespan(app: FastAPI):
    set_handlers(app, enabled_handler)
    yield


APP = FastAPI(lifespan=lifespan)
APP.add_middleware(AppAPIAuthMiddleware)


def enabled_handler(enabled: bool, nc: NextcloudApp) -> str:
    try:
        if enabled:
            nc.ui.top_menu.register(
                "pinboard",
                "Pinboard",
                "img/app.svg",
            )
            nc.log(LogLvl.WARNING, "Pinboard enabled — navigation entry registered")
        else:
            nc.ui.top_menu.unregister("pinboard")
            nc.log(LogLvl.WARNING, "Pinboard disabled — navigation entry removed")
    except Exception as e:
        return str(e)
    return ""


@APP.get("/pins")
async def get_pins(nc: Annotated[NextcloudApp, Depends(nc_app)]):
    """Return all pins for the current user."""
    nc.log(LogLvl.DEBUG, f"get_pins called by user: {nc.user}")
    return []


@APP.post("/pins")
async def create_pin(
    pin: PinRequest,
    nc: Annotated[NextcloudApp, Depends(nc_app)],
):
    """Create a new pin for the current user."""
    nc.log(LogLvl.DEBUG, f"create_pin called by user: {nc.user}, url: {pin.url}")
    return JSONResponse(
        content={"id": 1, "url": pin.url, "title": pin.title, "user_id": nc.user},
        status_code=201,
    )


if __name__ == "__main__":
    run_app("main:APP", log_level="trace")
```

# Run from: anywhere

> **The AppAPI proxy URL pattern:** ExApp endpoints are accessed through `http://nextcloud.local/apps/app_api/proxy/<app_id>/<your_path>`. AppAPI validates the request, attaches authentication headers, and forwards it to your server. This is how frontend code and curl reach your endpoints — not by calling your FastAPI port directly.

In your log tail terminal, watch for the debug messages as alice makes requests. Then open an incognito window and log in as `bob`, make the same GET request. Confirm the log shows `bob` as the user — each request is scoped to the authenticated Nextcloud user.

## Common problems

**Navigation entry doesn't appear after `make register`**  
Check the uvicorn terminal for errors during `enabled_handler`. Common cause: the `img/app.svg` file doesn't exist at the expected path. The icon path is relative to `ex_app/` — so `"img/app.svg"` maps to `ex_app/img/app.svg`.

**curl returns 401 on the proxy URL**  
You're using Basic Auth (`-u alice:alice`) which Nextcloud validates. If you get 401, check that `alice` is a valid user — verify at `http://nextcloud.local` by logging in manually.

**curl returns 404 on `/apps/app_api/proxy/pinboard_python/pins`**  
AppAPI isn't routing to your app. Check that the app is registered and enabled: `./scripts/occ.sh nextcloud -- app_api:app:list`. If it shows as disabled, check the uvicorn terminal — `enabled_handler` may have returned an error string.

**`nc.user` is empty or raises an error**  
This only happens if your endpoint is reached without AppAPI authentication — e.g. calling `http://localhost:23000/pins` directly instead of through the AppAPI proxy. Always test via the proxy URL.

**Pydantic validation error (422) on POST**  
Your request body is missing `url` or has the wrong format. FastAPI's 422 response includes a detailed message explaining exactly what failed — check the response body.
