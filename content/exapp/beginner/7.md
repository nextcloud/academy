## How user identity works in ExApps

In B-03 you used `nc.user` in your FastAPI endpoints to get the current user's ID. This section explains what's actually happening under the hood.

When a request comes in through the AppAPI proxy, AppAPI:

1. Reads the session cookie from the browser request to identify the logged-in Nextcloud user
2. Validates that the user is active and has permission to access the ExApp
3. Adds the `AUTHORIZATION-APP-API` header containing the user ID and shared secret
4. Forwards the request to your FastAPI server

`AppAPIAuthMiddleware` unpacks this header, validates the secret, and makes the user ID available. `nc_app()` — the FastAPI dependency you use with `Depends(nc_app)` — constructs a `NextcloudApp` instance authenticated as that user. `nc.user` then simply reads the user ID from that authenticated context.

This is why `nc.user` is always a non-empty string in your endpoints — if there's no valid user session, AppAPI returns 401 before your code ever runs.

**`nc.user` returns the Nextcloud login name** — a plain string like `alice` or `bob`. Not a numeric ID, not a display name. This is exactly what gets stored in your `user_id` database column.

## Adding getPin and deletePin endpoints

Add two new endpoints to `ex_app/lib/main.py`:

```python
# Run from: ~/pinboard-python/ (with .venv activated)
# Add to ex_app/lib/main.py

from fastapi import HTTPException

@APP.get("/pins/{pin_id}")
async def get_pin(
    pin_id: int,
    nc: Annotated[NextcloudApp, Depends(nc_app)],
    db: Session = Depends(get_session),
):
    """Fetch a single pin — only if it belongs to the current user."""
    pin = db.query(Pin).filter(
        Pin.id == pin_id,
        Pin.user_id == nc.user,
    ).first()

    if pin is None:
        raise HTTPException(status_code=404, detail="Not found")

    return pin.to_dict()


@APP.delete("/pins/{pin_id}")
async def delete_pin(
    pin_id: int,
    nc: Annotated[NextcloudApp, Depends(nc_app)],
    db: Session = Depends(get_session),
):
    """Delete a pin — only if it belongs to the current user."""
    pin = db.query(Pin).filter(
        Pin.id == pin_id,
        Pin.user_id == nc.user,
    ).first()

    if pin is None:
        raise HTTPException(status_code=404, detail="Not found")

    db.delete(pin)
    db.commit()
    nc.log(LogLvl.DEBUG, f"delete_pin: deleted pin {pin_id} for user {nc.user}")
    return {}
```

### The ownership pattern

Both endpoints filter on **both** `Pin.id == pin_id` **and** `Pin.user_id == nc.user`. If either condition fails — pin doesn't exist, or pin belongs to a different user — `.first()` returns `None` and you get a 404.

**Never return 403 for ownership failures.** Returning 403 ("forbidden") tells the caller that the resource exists but they can't access it. That's an information leak — it lets a user enumerate other people's pin IDs by probing for 403 vs 404. Always return 404 for both "not found" and "not yours."

This is the same principle as PHP M7's `DoesNotExistException` → 404 pattern.

## Add delete to the Vue UI

Update `src/App.vue` to add a delete button to each pin:

```vue
<!-- Replace the pin list item in the template: -->
<li v-for="pin in pins" :key="pin.id" class="pinboard__item">
  <a :href="pin.url" target="_blank" rel="noopener noreferrer">
    <strong>{{ pin.title || pin.url }}</strong>
    <span v-if="pin.title" class="pinboard__item__url">{{ pin.url }}</span>
  </a>
  <NcButton
    type="tertiary"
    :aria-label="t('pinboard_python', 'Delete pin')"
    @click="deletePin(pin.id)"
  >
    <template #icon><DeleteIcon :size="18" /></template>
  </NcButton>
</li>

<script>
// Add to imports:
import DeleteIcon from 'vue-material-design-icons/Delete.vue'
// Add DeleteIcon to components

// Add to methods:
async deletePin(pinId) {
  try {
    await axios.delete(
      generateUrl(`${APP_API_PROXY_URL_PREFIX}/${EX_APP_ID}/pins/${pinId}`)
    )
    this.pins = this.pins.filter(p => p.id !== pinId)
    showSuccess(t('pinboard_python', 'Pin deleted'))
  } catch (error) {
    console.error('Failed to delete pin', error)
    showError(t('pinboard_python', 'Failed to delete pin'))
  }
},
</script>

<style scoped>
/* Update the list item to flex with space-between */
.pinboard__item {
  padding: 12px 0;
  border-bottom: 1px solid var(--color-border);
  display: flex;
  align-items: center;
  justify-content: space-between;
  gap: 12px;
}
.pinboard__item a {
  display: flex; flex-direction: column; gap: 4px;
  color: var(--color-main-text); text-decoration: none;
  flex: 1;
}
</style>
```

**`this.pins = this.pins.filter(p => p.id !== pinId)`** — removes the pin from the local array immediately after a successful delete. No refetch needed — faster and feels instant.

## Common problems

**DELETE returns 405 Method Not Allowed**  
The route isn't in `info.xml`. Check that `<verb>` includes `DELETE`. Re-register with `make restart` after updating `info.xml`.

**DELETE returns 404 even for the user's own pins**  
Double-check the URL — the pin ID must be in the path, not as a query parameter. `DELETE /pins/1` is correct; `DELETE /pins?id=1` would not match the route.

**Pin disappears from UI but comes back on refresh**  
The `filter()` in `deletePin` is working but the server delete failed silently. Check that you're awaiting the `axios.delete()` before filtering — move the filter inside the `try` block after the await.
