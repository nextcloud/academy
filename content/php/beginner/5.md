## Why this matters

Before you can write a single Vue component, you need a build pipeline in place. Nextcloud app frontends are written in Vue 3 and compiled by Webpack before the browser ever sees them — raw `.vue` files and modern JavaScript syntax need to be transformed into something browsers understand.

This module gets that pipeline working. It's a one-time setup; once it's in place, Module 6 and everything after can focus entirely on building features.

---

## Concepts

### The frontend stack

Nextcloud apps use **Webpack** to bundle JavaScript, with `@nextcloud/webpack-vue-config` providing a pre-configured base. Your source files live in `src/` and Webpack outputs them to `js/`. The PHP template loads the built output.

In your `pinboard/` directory, create a new file named `package.json` and add the following contents:

```json
{
  "name": "pinboard",
  "version": "0.1.0",
  "private": true,
  "scripts": {
    "dev": "NODE_ENV=development webpack --config webpack.js",
    "watch": "NODE_ENV=development webpack --config webpack.js --watch",
    "build": "NODE_ENV=production webpack --config webpack.js"
  },
  "dependencies": {
    "@nextcloud/axios": "^2.5.0",
    "@nextcloud/dialogs": "^7.0.0",
    "@nextcloud/router": "^3.0.0",
    "@nextcloud/vue": "^9.0.0",
    "vue": "^3.4.0",
    "vue-material-design-icons": "^5.3.0"
  },
  "devDependencies": {
    "@nextcloud/webpack-vue-config": "^6.0.0",
    "css-loader": "^7.0.0",
    "terser-webpack-plugin": "^5.3.0",
    "vue-loader": "^17.0.0"
  }
}
```

What the scripts do:

- **`dev`** — builds once in development mode (unminified, with source maps for debugging)
- **`watch`** — same as `dev` but stays running and rebuilds automatically whenever you save a file
- **`build`** — builds once in production mode (minified, optimised for distribution)

You'll use `watch` during active development and `build` before packaging your app for release.

**Dependencies** — packages your app needs at runtime (shipped to the user's browser):

- **`vue`** — Vue 3, the component framework
- **`@nextcloud/vue`** — Nextcloud's component library (v9 for NC34), providing buttons, inputs, modals, navigation, and layout components that match the Nextcloud design system automatically
- **`@nextcloud/axios`** — a wrapper around Axios that automatically attaches the CSRF token to every request; required for all Nextcloud API calls (more on this in Module 6)
- **`@nextcloud/dialogs`** — toast notifications (`showSuccess`, `showError`) for user feedback
- **`@nextcloud/router`** — generates correct URLs to your endpoints regardless of the Nextcloud installation path
- **`vue-material-design-icons`** — the icon library used across the Nextcloud ecosystem

**devDependencies** — packages only needed during development and build time, not shipped to users:

- **`@nextcloud/webpack-vue-config`** — the base Webpack configuration; you extend it rather than writing your own
- **`vue-loader`** — teaches Webpack how to process `.vue` single-file components (the `<template>`, `<script>`, `<style>` blocks)
- **`css-loader`** — teaches Webpack how to process CSS, including the `<style scoped>` blocks in `.vue` files

> **dependencies vs devDependencies:** The distinction matters mainly for library authors and CI pipelines — `npm install --production` skips devDependencies, keeping deployment images lean. For app development like this course, both get installed by a plain `npm install` so day-to-day you won't notice the difference. The rule of thumb: if it's something your built `js/main.js` imports, it's a dependency; if it's only involved in the build process itself, it's a devDependency.

> **`@nextcloud/vue` component catalogue:** As you build, keep [nextcloud-vue-components.netlify.app](https://nextcloud-vue-components.netlify.app/) open in a second tab. It lists every available component with live examples and prop documentation — useful for discovering what exists before reaching for custom HTML.

Next, in the same directory, create a new file named `webpack.js` and add the following contents:

```js
/**
 * SPDX-FileCopyrightText: 2025 Your Name
 * SPDX-License-Identifier: AGPL-3.0-or-later
 */

const path = require('path')
const webpackConfig = require('@nextcloud/webpack-vue-config')

module.exports = {
  ...webpackConfig,
  entry: {
    main: path.join(__dirname, 'src', 'main.js'),
  },
  output: {
    ...webpackConfig.output,
    path: path.resolve(__dirname, 'js'),
    filename: '[name].js',
    chunkFilename: '[name]-[contenthash].js',
  },
}
```

A few things to understand:

**`@nextcloud/webpack-vue-config`** provides a complete, pre-configured Webpack setup for Nextcloud apps — Vue loader, CSS loader, minification, source maps, and output paths all configured correctly. You don't need to know how Webpack works in depth to use it.

**`...webpackConfig`** — the spread operator copies all properties from the base config into your config object. Any property you define after it overrides the base; anything you don't define keeps the base config's value. Here we override `entry` and `output`, leaving everything else (loaders, optimisation) untouched.

**`entry`** tells Webpack where your application starts. `src/main.js` is the root file that imports Vue, mounts your app, and pulls in all other components. Webpack follows the import chain from this file and bundles everything it finds into `js/main.js`. If you later add a second independent script (say, for a settings page), you'd add a second entry here.

**`path.join(__dirname, 'src', 'main.js')`** builds an absolute path to `src/main.js` relative to `webpack.js` itself. Using `path.join` rather than a hardcoded string ensures the path works correctly regardless of which directory you run Webpack from.

**`output`** tells Webpack where to write the bundled files and what to name them. `...webpackConfig.output` keeps the base config's other output settings; `path: path.resolve(__dirname, 'js')` is what makes the compiled bundle land in `js/main.js` (the file `\OCP\Util::addScript('pinboard', 'main')` loads later in this module) rather than the base config's default location. `filename` names the main bundle, and `chunkFilename` names any additional chunks Webpack splits off — Vue's async components, for instance.

**3. Install dependencies**

This module requires Node 24 — the version NC34 itself uses. We use **nvm** (Node Version Manager) to install and manage it — it's the simplest way to get the right version without touching your system's global Node installation.

**Step 1: Install nvm** (run `nvm --version` in your terminal anywhere — if it prints a version number, nvm is already installed and you can go straight to Step 2)

Download and inspect the install script before running it:

```bash
# Download the install script without executing it
curl -o nvm-install.sh https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.2/install.sh

# Review it — less is a terminal pager: scroll with arrow keys, press q to quit
less nvm-install.sh

# Once satisfied, execute it
bash nvm-install.sh

# Clean up
rm nvm-install.sh

# Restart your terminal, then verify:
nvm --version
```

**Step 2: Install and use Node 24**

```bash
nvm install 24       # download and install Node 24
nvm use 24           # use it in the current shell
nvm alias default 24 # make it the default for all future shells
```

Verify with `node --version` — you should see `v24.x.x`.

**Step 3: Install npm packages**

```bash
# Run from: workspace/server/apps-extra/pinboard/
npm install
```

This reads `package.json`, downloads all listed packages into `node_modules/`, and creates `package-lock.json` which locks exact versions for reproducible installs. Run it once now, and again any time you add a package to `package.json` by hand.

A few things worth knowing as you work:

- **`npm install` vs `npm ci`** — `npm install` is for development: it installs packages and keeps `package-lock.json` up to date. `npm ci` is a stricter variant for CI pipelines that installs exactly what's in `package-lock.json` and never modifies it. Use `npm install` locally.

- **Adding packages** — `npm install <package-name>` both downloads the package *and* adds it to `package.json` automatically, saving you the manual edit step. For example, `npm install vue-material-design-icons` is equivalent to adding it to `package.json` and then running `npm install`.

- **`node_modules/` and git** — `npm install` populates a `node_modules/` directory that can contain tens of thousands of files and should never be committed. The scaffold's `.gitignore` already covers this. If you ever start an app from scratch, add `node_modules/` to `.gitignore` before your first commit.

- **Committing built output** — whether to commit the built `js/` directory is up to you. Many Nextcloud app repos do commit it so the app can be installed without a build step. Either approach is fine, just be consistent. The scaffold leaves this decision to you.

### Loading the built script in the PHP template

The compiled JavaScript needs to be included in the page. Update `templates/main.php`:

```php
<?php
/**
 * SPDX-FileCopyrightText: 2025 Your Name
 * SPDX-License-Identifier: AGPL-3.0-or-later
 */
/** @var \OCP\IL10N $l */
/** @var \OCP\Defaults $theme */
\OCP\Util::addScript('pinboard', 'main');
?>
<div id="app-pinboard"></div>
```

Two things to note about this template:

**`\OCP\Util::addScript('pinboard', 'main')`** tells Nextcloud to load `js/main.js` — the file Webpack will produce. The first argument is the app ID, the second is the script name without the `.js` extension. This call goes in the PHP block at the top so the script is registered before the page renders.

**The empty `<div id="app-pinboard">`** is the entire page body. This is the standard single-page app pattern — PHP renders a minimal HTML shell with one mount point, and Vue takes over from there. Every component, every list item, every button will be rendered by Vue into this div at runtime. The ID must match exactly what you pass to `app.mount()` in `src/main.js` — a mismatch means Vue silently fails to mount and you see a blank page.

> **Why not `<script src="...">` directly?** `\OCP\Util::addScript()` is how Nextcloud manages script loading — it handles ordering, deduplication, and Content Security Policy compliance. Never include scripts via raw `<script>` tags in Nextcloud templates.

### The Vue entry point

Create `src/main.js`:

```js
/**
 * SPDX-FileCopyrightText: 2025 Your Name
 * SPDX-License-Identifier: AGPL-3.0-or-later
 */

import { createApp } from 'vue'
import App from './App.vue'

const app = createApp(App)
app.mount('#app-pinboard')
```

**`import { createApp } from 'vue'`** — imports the `createApp` function from the Vue 3 package. Note this is `vue`, not `@nextcloud/vue` — they're two different packages. `vue` is the core Vue 3 framework itself (the engine that makes components, reactivity, and rendering work). `@nextcloud/vue` is a separate library built on top of it that provides Nextcloud-specific UI components like `NcButton` and `NcAppContent`. `@nextcloud/vue` lists `vue` as a peer dependency, meaning it requires `vue` to be present but won't install it for you — that's why both appear in `package.json`. The curly braces are JavaScript's named import syntax — Vue exports many functions, and this pulls in just the one you need rather than the entire library.

**`import App from './App.vue'`** — imports your root component. The `./` means "relative to this file", so Webpack looks for `App.vue` in the same `src/` directory as `main.js`. The `.vue` extension tells Webpack to hand the file to `vue-loader`, which processes the `<template>`, `<script>`, and `<style>` blocks and turns them into a JavaScript object that Vue can work with.

**`createApp(App)`** creates a Vue application instance from your root component. `App` here is the `App.vue` component you'll build in Module 6 — it's the top of the component tree that everything else lives inside.

**`app.mount('#app-pinboard')`** finds the `<div id="app-pinboard">` in the PHP template and hands control of it to Vue. From this point on, Vue owns that div — it renders your components into it, handles reactivity, and manages the DOM. The string `'#app-pinboard'` is a CSS selector, so it must match the `id` attribute in `templates/main.php` exactly.

This four-line pattern is the standard Vue 3 entry point. Every Vue app starts here — one import of `createApp`, one import of the root component, one `createApp`, one `mount`.

## Common problems

**Webpack fails with "Cannot find module '@nextcloud/webpack-vue-config'"**  
You haven't run `npm install` yet, or it failed silently. Run it again and check for errors.

**`js/main.js` is not created after `npm run dev`**  
Check the Webpack output for errors. A syntax error in `webpack.js` or a missing `src/main.js` are the most common causes.

**The page shows a 404 or doesn't load at all**  
Check that `\OCP\Util::addScript('pinboard', 'main')` is in `templates/main.php` and that the app is enabled: `./scripts/occ.sh nextcloud -- app:list --enabled | grep pinboard`.
