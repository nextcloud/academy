The toolchain from Module 5 is in place — Webpack is compiling, the PHP template has a mount point, and `main.js` is ready. Now you build the actual interface.

This module introduces the core patterns you'll use in every Nextcloud Vue component you write: `@nextcloud/vue` components, `@nextcloud/axios` for API calls, CSS variables for theming, and the `@nextcloud/dialogs` toast system. ## Before you start

Before diving into the component, start Webpack in watch mode. Unlike `npm run dev` which builds once and exits, watch mode stays running and recompiles your JavaScript automatically every time you save a `.vue` or `.js` file. This means you can edit code, save, hard reload the browser, and see the result immediately — no manual rebuild step between every change.

Run this in a separate terminal and leave it running for the rest of the module:

```bash
# Run from: workspace/server/apps-extra/pinboard/
npm run watch
```

When a file changes you'll see Webpack print a new compilation result in that terminal. After it finishes, hard reload the browser (`Ctrl+Shift+R` / `Cmd+Shift+R`) to pick up the new bundle — a normal reload may serve the cached previous version.

## Concepts

### Vue single-file components

Every Vue component in a Nextcloud app is a `.vue` file made up of three blocks:

- **`<template>`** — the HTML structure of the component. This is what gets rendered into the DOM. It can only have one root element.
- **`<script>`** — the component's logic: its data, methods, lifecycle hooks, and imports. This is where you fetch data, handle user interactions, and register child components.
- **`<style scoped>`** — the component's CSS. The `scoped` attribute means these rules only apply to elements inside this component and won't leak out to affect other parts of the Nextcloud UI.

Webpack's `vue-loader` (which you added in Module 5) processes these three blocks and compiles them into JavaScript the browser can run. You never need to split your component across multiple files — everything that belongs together stays together.

---

### Exposing translation helpers globally

Every component you write from here on will wrap user-facing strings in `t('pinboard', '...')` for translation. Rather than importing and re-exposing `t` in every single component, register it once as a global mixin so every component in the app can call `this.t(...)` — and, since Vue's template compiler resolves bare identifiers like `t(...)` against the component instance, that also makes `t(...)` work directly inside `<template>` blocks with no per-component wiring.

Update `src/main.js`:

```js
import { createApp } from 'vue'
import { n, t } from '@nextcloud/l10n'
import App from './App.vue'

const app = createApp(App)
app.mixin({
  methods: { t, n },
})
app.mount('#app-pinboard')
```

**What's a mixin?** Think of it as a shared toolbox that gets handed to every component automatically. Normally, if a component needs a function, you import it yourself at the top of that component's file. A mixin skips that step: whatever you put inside `app.mixin(...)` — here, the `t` and `n` functions — becomes available on every single component in your app, as if it had always been there. You set it up once, in `main.js`, and never have to think about it again in the components you write afterwards.

**`app.mixin({ methods: { t, n } })`** merges `t` (translate) and `n` (pluralise, e.g. "1 pin" vs "2 pins") into every component's `methods`, application-wide. This is the same pattern Nextcloud's own first-party apps use — for example `CommentsInstance.ts` in the `comments` app registers `t` and `n` the same way right after `createApp(...)`. Without this, calling `t(...)` from a component's `<template>` throws `_ctx.t is not a function`, because Vue only resolves template identifiers against the component instance — importing `t` into a `<script>` block does not, by itself, make it available in that component's template.

Two call sites, two forms: inside a `<template>`, write it bare — `t('pinboard', '...')` — Vue resolves it against the instance automatically. Inside a `<script>` method, write `this.t('pinboard', '...')` — methods are plain JavaScript functions, so `t` has to be reached through `this` like any other mixed-in method.

### Building `src/App.vue` step by step

Create `src/App.vue` and build it up in stages. Each step below adds to the previous one — by the end you'll have a working component and understand why each piece is there.

#### Step 1: The skeleton and imports

Start with the foundation — the imports, component registration, data properties, and a minimal `<template>` with just a heading. This step won't look like much in the browser, but it establishes the full structure that Steps 2 and 3 build on, and makes the first API call to fetch pins as soon as the component mounts.

```vue
<!--
  SPDX-FileCopyrightText: 2025 Your Name
  SPDX-License-Identifier: AGPL-3.0-or-later
-->
<template>
  <NcAppContent>
    <div class="pinboard">
      <h2>{{ t('pinboard', 'Your pins') }}</h2>
    </div>
  </NcAppContent>
</template>

<script>
import axios from '@nextcloud/axios'
import { showError, showSuccess } from '@nextcloud/dialogs'
import '@nextcloud/dialogs/style.css'
import { generateUrl } from '@nextcloud/router'
import {
  NcAppContent,
} from '@nextcloud/vue'

export default {
  name: 'App',

  components: { NcAppContent },

  data() {
    return {
      pins: [],
      loading: false,
    }
  },

  mounted() {
    this.fetchPins()
  },

  methods: {
    async fetchPins() {
      this.loading = true
      try {
        const response = await axios.get(generateUrl('/apps/pinboard/pins'))
        this.pins = response.data
      } catch (error) {
        console.error('Failed to fetch pins', error)
      } finally {
        this.loading = false
      }
    },
  },
}
</script>

<style scoped>
.pinboard {
  padding: 20px;
  max-width: 800px;
}
</style>
```

**What's here:**

**`<template>`**

- **`NcAppContent`** — always the outermost element in a Nextcloud app page. It handles correct margins, scroll behaviour, and integration with the app navigation frame.

**`<script>`**

- **`@nextcloud/axios`** — a drop-in replacement for Axios that automatically attaches the `requesttoken` CSRF header to every request. Nextcloud rejects POST, PUT, and DELETE requests without it with a 401. Never use `fetch` or plain `axios` for Nextcloud API calls. More on this below.
- **`generateUrl()`** from `@nextcloud/router` — builds the correct URL to your endpoint regardless of how Nextcloud is installed. If Nextcloud lives at a subdirectory (`nextcloud.local/nc/`), `generateUrl` handles the prefix. Never hardcode URLs.
- **`t()`** — wraps strings for translation. Even if you're not shipping translations yet, wrapping from day one means you never have to retrofit it. Notice `App.vue` doesn't import it — it's available as `this.t` (and directly as `t(...)` in the template) because of the global mixin you registered in `src/main.js` above. That's true for every component you write from here on, not just this one.
- **`mounted()`** — Vue lifecycle hook that runs after the component is inserted into the DOM. This is where you kick off the initial data fetch.

**`<style scoped>`**

- The `scoped` attribute means these rules only apply to elements inside this component — they won't leak out and accidentally affect other parts of the Nextcloud UI.

Build and hard reload (`Ctrl+Shift+R` on Linux/Windows, `Cmd+Shift+R` on macOS) — you should see "Your pins" as a heading. Nothing else yet.

#### Step 2: Display pins

With the data fetching in place, add the UI to actually show it. This step introduces three rendering states — loading, has pins, and empty — along with the `@nextcloud/vue` components for each. You'll also add the CSS variables that make the list adapt to Nextcloud's themes automatically.

Still in `src/App.vue` — update the `<template>` block and add to the `<script>` imports, `components`, and `<style scoped>`:

```vue
<template>
  <NcAppContent>
    <div class="pinboard">
      <h2>{{ t('pinboard', 'Your pins') }}</h2>

      <div v-if="loading && pins.length === 0" class="pinboard__loading">
        <NcLoadingIcon :size="32" />
      </div>

      <ul v-else-if="pins.length > 0" class="pinboard__list">
        <li v-for="pin in pins" :key="pin.id" class="pinboard__item">
          <a :href="pin.url" target="_blank" rel="noopener noreferrer">
            <strong>{{ pin.title || pin.url }}</strong>
            <span v-if="pin.title" class="pinboard__item__url">{{ pin.url }}</span>
          </a>
        </li>
      </ul>

      <NcEmptyContent
        v-else
        :name="t('pinboard', 'No pins yet')"
        :description="t('pinboard', 'Add your first pin to get started.')"
      >
        <template #icon>
          <PinIcon :size="64" />
        </template>
      </NcEmptyContent>
    </div>
  </NcAppContent>
</template>
```

Update the `<script>` imports and `components`:

```js
import {
  NcAppContent,
  NcEmptyContent,
  NcLoadingIcon,
} from '@nextcloud/vue'
import PinIcon from 'vue-material-design-icons/Pin.vue'

// in components:
components: { NcAppContent, NcEmptyContent, NcLoadingIcon, PinIcon },
```

Add the new styles to `<style scoped>`:

```css
.pinboard__list {
  list-style: none;
  padding: 0;
  margin: 0;
}

.pinboard__item {
  padding: 12px 0;
  border-bottom: 1px solid var(--color-border);
}

.pinboard__item a {
  display: flex;
  flex-direction: column;
  gap: 4px;
  color: var(--color-main-text);
  text-decoration: none;
}

.pinboard__item a:hover strong {
  text-decoration: underline;
}

.pinboard__item__url {
  font-size: 0.85em;
  color: var(--color-text-maxcontrast);
}

.pinboard__loading {
  display: flex;
  justify-content: center;
  padding: 40px;
}
```

**What's new:**

- **`v-if` / `v-else-if` / `v-else`** — Vue's conditional rendering. The three states are: loading with no pins yet (spinner), has pins (list), no pins at all (empty state). The order matters — `v-if` is checked first.
- **`v-for`** — renders a list item for each pin. The `:key` is required and should be a unique, stable value — `pin.id` is perfect.
- **`NcEmptyContent`** — the standard Nextcloud empty-state component. Always use this rather than custom "nothing here" text — it follows the Nextcloud design pattern and supports an icon slot.
- **`NcLoadingIcon`** — the standard spinner. Use this instead of a custom loading indicator.
- **CSS variables** — `var(--color-border)`, `var(--color-main-text)`, `var(--color-text-maxcontrast)` are defined by Nextcloud's theming system. Using them instead of hardcoded colours matters for three reasons. First, Nextcloud supports light and dark mode — hardcoded colours like `#333` that look fine in light mode become invisible or jarring in dark mode, while CSS variables switch automatically. Second, Nextcloud instances can be themed by administrators with custom brand colours — your app will inherit those automatically if you use variables, and stick out if you don't. Third, some variables like `--color-text-maxcontrast` are specifically chosen to meet WCAG contrast ratios against their expected backgrounds, so using them gives you accessible contrast for free rather than having to calculate it yourself. The full list of available variables is in the [Nextcloud theming docs](https://docs.nextcloud.com/server/stable/developer_manual/basics/front-end/theming.html#css-variables).
- **`vue-material-design-icons`** — the icon library used throughout the Nextcloud app ecosystem. Icons are individual `.vue` files imported by name. The `size` prop controls pixel dimensions (default 24). The full icon list is at [MaterialDesignIcons.com](https://materialdesignicons.com) — import paths use PascalCase with `.vue` appended: `Pin.vue`, `Plus.vue`, `AccountCircle.vue` and so on.

Build and hard reload (`Ctrl+Shift+R` / `Cmd+Shift+R`) — you should now see the "No pins yet" empty state, or your existing pins from M4 if you created any.

#### Step 3: The "Add pin" form

The last piece — a button that opens a modal with a form to create new pins. This step introduces `NcButton`, `NcModal`, and `NcTextField`, wires up the `createPin` method that posts to the API, and adds toast notifications so the user gets clear feedback on success or failure.

Still in `src/App.vue` — update the `<template>`, add to `<script>` imports, `components`, `data()`, and `methods`, then add the final styles to `<style scoped>`:

```vue
<template>
  <NcAppContent>
    <div class="pinboard">
      <div class="pinboard__header">
        <h2>{{ t('pinboard', 'Your pins') }}</h2>
        <NcButton type="primary" @click="showAddForm = true">
          <template #icon>
            <PlusIcon :size="20" />
          </template>
          {{ t('pinboard', 'Add pin') }}
        </NcButton>
      </div>

      <NcModal v-if="showAddForm" @close="showAddForm = false">
        <template #default>
          <div class="pinboard__add-form">
            <h3>{{ t('pinboard', 'Add a new pin') }}</h3>
            <NcTextField
              :label="t('pinboard', 'URL')"
              v-model="newPin.url"
              :error="!!urlError"
              :helper-text="urlError"
              @keydown.enter="createPin"
            />
            <NcTextField
              :label="t('pinboard', 'Title (optional)')"
              v-model="newPin.title"
              @keydown.enter="createPin"
            />
            <div class="pinboard__add-form__actions">
              <NcButton @click="showAddForm = false">
                {{ t('pinboard', 'Cancel') }}
              </NcButton>
              <NcButton type="primary" :disabled="loading" @click="createPin">
                {{ t('pinboard', 'Save') }}
              </NcButton>
            </div>
          </div>
        </template>
      </NcModal>

      <!-- pin list and empty state from Step 2 — unchanged -->
    </div>
  </NcAppContent>
</template>
```

Update `<script>` imports, `components`, `data()`, and add the `createPin` method:

```js
import {
  NcAppContent,
  NcButton,
  NcEmptyContent,
  NcLoadingIcon,
  NcModal,
  NcTextField,
} from '@nextcloud/vue'
import PinIcon from 'vue-material-design-icons/Pin.vue'
import PlusIcon from 'vue-material-design-icons/Plus.vue'

// in components:
components: { NcAppContent, NcButton, NcEmptyContent, NcLoadingIcon, NcModal, NcTextField, PinIcon, PlusIcon },

// add to data():
showAddForm: false,
newPin: { url: '', title: '' },
urlError: '',

// add to methods:
async createPin() {
  this.urlError = ''
  if (!this.newPin.url.trim()) {
    this.urlError = this.t('pinboard', 'URL is required')
    return
  }

  this.loading = true
  try {
    const response = await axios.post(
      generateUrl('/apps/pinboard/pins'),
      {
        url: this.newPin.url.trim(),
        title: this.newPin.title.trim() || null,
      }
    )
    this.pins.unshift(response.data)
    this.newPin = { url: '', title: '' }
    this.showAddForm = false
    showSuccess(this.t('pinboard', 'Pin saved'))
  } catch (error) {
    console.error('Failed to create pin', error)
    showError(this.t('pinboard', 'Failed to save pin'))
  } finally {
    this.loading = false
  }
},
```

Add the remaining styles:

```css
.pinboard__header {
  display: flex;
  align-items: center;
  justify-content: space-between;
  margin-bottom: 24px;
}

.pinboard__add-form {
  padding: 24px;
  display: flex;
  flex-direction: column;
  gap: 16px;
  min-width: 400px;
}

.pinboard__add-form__actions {
  display: flex;
  justify-content: flex-end;
  gap: 8px;
}
```

**What's new:**

- **`NcButton`** — Nextcloud's button component. The `type` prop controls the visual style: `primary`, `secondary` (default), `tertiary`, `error`, `success`, `warning`. The `#icon` slot accepts a component — always pass an icon this way rather than embedding it in the button text.
- **`NcModal`** — a dialog/overlay. Handles focus trapping, keyboard dismissal, and accessible ARIA roles automatically. Use `v-if` rather than `v-show` so the modal is fully removed from the DOM when closed.
- **`NcTextField`** — a labelled text input. Always use this rather than a plain `<input>` — it handles label association, error states, and accessibility correctly. Bind it with `v-model="newPin.url"` for two-way binding — Vue keeps the field and `newPin.url` in sync automatically. (Older Vue 2 code you might come across uses `:value.sync="newPin.url"` for the same purpose; `.sync` was removed in Vue 3, so `@nextcloud/vue` v9 components use `v-model` instead.)
- **`pins.unshift(response.data)`** — adds the new pin to the front of the list immediately without a full refetch. This is the optimistic update pattern — the UI responds instantly and the data is already in sync since the server returned the created pin.
- **`showSuccess()` / `showError()`** from `@nextcloud/dialogs` — Nextcloud's toast notification system. `showSuccess` shows a green confirmation banner; `showError` shows a red error banner. Import them from `@nextcloud/dialogs` and call them after any operation the user needs feedback on. Note the accompanying CSS import (`import '@nextcloud/dialogs/style.css'`) — without it the toasts render without styling. This import goes in `main.js` once and applies globally.

Build and hard reload (`Ctrl+Shift+R` / `Cmd+Shift+R`) — the full Pinboard UI is now working.

### CSRF and why `@nextcloud/axios` exists

You've now used `@nextcloud/axios` in two places — `fetchPins` and `createPin`. This section explains what it actually protects against and how.

**What is CSRF?**

Cross-Site Request Forgery (CSRF) is an attack where a malicious website causes a logged-in user's browser to make a request to a different site — one the user is already authenticated with — without their knowledge.

Here's a concrete example. You're logged into your Nextcloud instance. You visit an unrelated malicious website. That page contains:

```html
<img src="https://your-nextcloud.com/index.php/apps/pinboard/pins?url=http://evil.com" />
```

Or more dangerously, a hidden form that auto-submits on page load:

```html
<form method="POST" action="https://your-nextcloud.com/index.php/apps/pinboard/pins">
  <input name="url" value="http://evil.com" />
</form>
<script>document.forms[0].submit()</script>
```

Your browser will send this request including your Nextcloud session cookie — because the browser always sends cookies for a domain regardless of which page initiated the request. The server has no way to tell the request came from a malicious site rather than Nextcloud's own frontend.

**How Nextcloud protects against it**

Nextcloud uses the **synchronizer token pattern**. When Nextcloud renders a page, it embeds a unique random token (`requesttoken`) in the page that only the legitimate Nextcloud frontend knows. Any state-changing request (POST, PUT, DELETE) must include this token as a request header. The server validates it — if it's missing or wrong, the request is rejected with a 401.

A malicious third-party page cannot access this token because of the browser's same-origin policy: JavaScript on `evil.com` cannot read the content of pages on `nextcloud.com`.

**What `@nextcloud/axios` does**

`@nextcloud/axios` is a thin wrapper around Axios that reads the `requesttoken` from `OC.requestToken` (injected into the page by Nextcloud) and automatically attaches it as a request header on every request:

```
requesttoken: abc123xyz...
```

This is why you must use `@nextcloud/axios` instead of `fetch` or plain `axios` — those don't know about the token and your POST requests will fail with a 401. The fix is always the same: check your import.

```js
// ✅ Correct — CSRF token attached automatically
import axios from '@nextcloud/axios'

// ❌ Wrong — no CSRF token, will get 401 on POST/PUT/DELETE
import axios from 'axios'
// or
fetch(url, { method: 'POST', ... })
```

## Common problems

**The page loads but shows a blank white area instead of the Vue app**  
Open browser devtools console. A Vue mounting error usually means `#app-pinboard` wasn't found, which means `\OCP\Util::addScript()` didn't load the script before the div rendered, or the div ID doesn't match. Check that `templates/main.php` has `id="app-pinboard"` and that `\OCP\Util::addScript('pinboard', 'main')` is called before the div.

**POST requests return 401**  
The CSRF token is missing. Check that you're importing `axios` from `@nextcloud/axios`, not from `axios` directly.

**`generateUrl` returns a wrong path**  
If Nextcloud is installed in a subdirectory on your instance, hardcoded URLs won't work. Always use `generateUrl()` from `@nextcloud/router`.

**Icons don't render**  
`vue-material-design-icons` is probably not installed, or the import path is wrong. Run `npm install vue-material-design-icons` and rebuild. Check that imports use the full path format: `import PinIcon from 'vue-material-design-icons/Pin.vue'` — not a named import from a package root.

**`NcTextField` shows a `.sync` warning, or two-way binding doesn't work**  
If you're referencing older Nextcloud code or tutorials, you may see `:value.sync="newPin.url"` — that's the Vue 2 syntax. `.sync` was removed in Vue 3; `@nextcloud/vue` v9 components use `v-model` instead, as shown above.

> **Note:** The `NcTextField` code above uses the v9 API. Check the `@nextcloud/vue` component documentation for the exact props if you see warnings, as the API evolves between minor versions.

## NC34 notes

NC34 uses Vue 3 and `@nextcloud/vue` v9. If you encounter older tutorials or apps using Vue 2 patterns — `Vue.component()`, `new Vue({})`, the Options API with `Vue.extend` — those are the pre-NC33 approach. NC34 apps should use Vue 3's `createApp()` pattern as shown here.

The global `OC.Notifications` and `OC.dialogs` APIs from older Nextcloud versions are gone in NC34. The `@nextcloud/dialogs` package used throughout this module is their replacement — `showSuccess` and `showError` for toasts, with additional functions for confirmation dialogs available as your app grows.
